**Completeness:** the run ran its full 10 h and was not stopped early. Every container has 2,400/2,400 samples, and the

| postgres / caddy, all samples | +0.05 / +0.10 | |

**Verdict: the api grows slowly and the growth is slowing; it is plateauing, not oscillating.** The baseline rose
4.7 MB over 9 h (131.8 → 136.5). The rate fell from +0.83 MB/h in the first 4 h to about +0.1 MB/h in the last 3 h,
which looks like caches and a GC heap settling rather than an unbounded leak. A 10 h run can't rule out
slow long-term growth. Even at the full-night rate of +0.49 MB/h without any flattening, the api would
take about 13 days to go from 137.8 to 300 MB, so the decision holds. Check it again on the VM after a few days
of uptime (I4).

## Caveats

- **Platform: Windows x86_64 Docker Desktop, not Apple Silicon.** The run was on a Windows 11 x86_64 machine
  (Docker Desktop's Linux VM), so the images are the same `linux/amd64` architecture as the target VM. No arm64
  difference applies. Docker Desktop's VM kernel and memory accounting can still differ slightly from the Azure VM's.
- **No Azure VM OS/agent overhead** is included: the guest OS, Docker daemon, Azure agents and the page cache all need
  room in the 1 GiB. Verify with `free -m` on the VM in I4. The containers' peaks sum to 211.5 MB here.
- **No real push notifications were sent.** The tester has a *dummy* FCM token and alert minutes `[5,10,30]` but no
  pass subscriptions. Every notification tick therefore ran its real queries (settings, upcoming passes, subscriptions), but
  no FCM send ever happened. Memory for real sends (Firebase client, HTTP/2 to FCM) is not measured.
- **Single tester, light synthetic load** (about 8.6 requests/min). Beta use with several testers will add request
  memory, although the DB-backed endpoints are cheap (p95 under 70 ms).
- **10-hour window:** the slow baseline growth (+0.49 MB/h overall, about +0.1 MB/h at the end) should be
  checked again after several days of uptime on the VM.
- **Sampling:** docker stats every 15 s can miss sub-second memory or CPU spikes. Docker reports memory usage
  excluding the inactive file cache.
